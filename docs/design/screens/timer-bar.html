One arrangement holds every state. Identity holds the left edge and the readout the right, so the clock lands in the same place whether a timer is running, idle or overdue — the number a glance goes to does not move as the name beside it changes length. The bar sits under the panel at the panel's width, which is what keeps the two ends reading as one object.

375px cannot hold four objects plus a seven-character clock on one line — two truncated words are worse than one whole one. Each row is one idea rather than a queue of fragments, and the transport keeps the right edge on both, so the control is under the thumb wherever the row breaks.

What the rendering cannot show
  • The running task name is text, with an explicit rename button. As a live <input> a stray click renamed billable work, and the bar looked like a form waiting for input on every screen. The pencil is always rendered — hover does not exist on touch, and this is the one control with no other route.
  • The name shrinks but never grows. The clock is placed by margin-left:auto, so a greedy name would walk the tag rightward and push the readout off its edge. Shrink-only keeps the right edge fixed and lets a long name truncate instead.
  • The first row is one grouped element, dissolving at sm with contents. Flex-wrap moves items before it shrinks them, so as loose siblings the project tag took a line of its own instead of letting the name truncate beside it.
  • The runaway bar does not grow. Chrome must not reflow to report a problem. The choice — Keep · Adjust · Discard — lives in the inbox; screens/home.html specifies it.
  • useRunaway holds that state (lib/client/use-runaway.ts), because the row and the editor Adjust opens are in different components: the inbox is in the dock, the EntryDialog stays here. The stopped entry crosses between them through a small module-level store rather than a provider wrapping the whole app to carry one occasional value.

Entering seeds the draft from the server's name, so the draft and the mode are one piece of state that cannot disagree. focus() must precede select() — selecting does not focus, and without focus the field opens with no cursor and never fires the blur that commits.

Counting

useTimer counts locally from startedAt and reconciles with /summary every 60s and on focus. serverTime corrects a skewed device clock.

  • Before hydration it counts from the server's timestamp, not Date.now() — otherwise SSR and the client render different seconds and React reports a mismatch.
  • Today's total subtracts the running timer's elapsed-at-fetch before adding the live count, or the running time is counted twice.

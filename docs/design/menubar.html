Stint in the menu bar

One design, three states. Built from the app's own tokens and components — same accent, same neutral ramp, same mono readout, same round transport button as the docked timer bar. Rendered at 320px, a real popover width.

This is the spec. The panel is 320pt wide; heights follow content — running ≈ 428, stopped ≈ 425, runaway ≈ 276. A MenuBarExtra in .menuBarExtraStyle(.window), which is a plain panel hanging from the bar — there is no arrow here.

Catching a runaway is why this app is worth building. Stopping and starting a timer are what it does more often, but a timer forgotten at 5pm is the most common way a tracker produces a wrong invoice, and the menu bar is the only surface that can say so without the user opening anything. It is not a port of the web app: no calendar, no invoicing, no client management, and no settings beyond the four rows below.

  • A dot, not a letterform. A filled circle means recording in a way a letter cannot — it is what every camera and every recorder uses — and the status item's whole job is to say whether time is accruing.
  • Three fills: accent running, timerIdle stopped, amber past the threshold. The amber one matters most — it is how a runaway reaches someone whose panel is closed.
  • Findability is the honest cost. A bare dot is harder to pick out of a crowded bar than a letter, and people will learn its position rather than recognise its shape. That is how most menu bar apps are actually found; do not re-add a letterform to compensate.
  • Identity lives in the panel header, where there is room for the mark at full size and a 12pt glyph is not being asked to do branding.

Settings — same panel, pushed
  • Not a second popover, not a window. Two stacked shadows at 320pt read as a mistake, and a separate Settings window needs a Dock icon to be recoverable — which LSUIElement exists to avoid. A pushed view needs neither.
  • The header swaps to a back affordance. One way in, one way out. Escape also returns.
  • Reopening the panel returns to the timer, never to settings. Settings is somewhere you visit, not a state the panel remembers.
  • Two rows, and the bar for a third is high. Rates, clients, invoice identity and payment profiles are business configuration and live in the web app — the same argument that keeps Settings out of the web app's nav rail. The runaway threshold is the server's (/summary decides exceedsThreshold) and the global shortcut is unbuilt; neither is drawn here until it can do something.

Tokens, type and controls

Use the generated tokens; never type a hex. Tokens.swift is written into the app's own sources by pnpm tokens, because SwiftPM cannot read the gitignored dist/. The app is dark-only, so use Tokens.Dark — light mode needs the same explicit choice the web app makes, not an @Environment(\.colorScheme) read.

Green means time is accruing, and may appear as many times as that one idea occurs: the pip and the readout while running, or the start button while stopped.   • Every number is mono with .monospacedDigit(). A readout that reflows as its digits change is the exact thing the rule exists to prevent.
  • The scale is mirrored from tokens.json by hand, and the faces fall back to the system's. Both are tasks.md lines: emitting the scale into Tokens.swift, and shipping Plex with the app.
  • Text fields: bgPrimary fill, 8pt radius, 34pt high, 14pt sans. Buttons: same radius and height, 14pt sans medium. Hit targets 28pt minimum — a menu bar panel is used in a hurry.
  • Focus is a ring change, never a fill change. A field that changes background on focus reads as a different control. AppKit draws its own blue ring unless the field is .textFieldStyle(.plain) with an explicit overlay.
  • Something is always focused when the panel opens — the task field when stopped, the email or code field in sign-in. A panel you must click into wastes the interaction it exists to shorten.
Talking to the server

Everything goes through /api/v1/* with a bearer token from the Keychain. There is no Swift-specific endpoint and there should not be one — the API is the shared contract.

EndpointFor
GET /timer/currentThe running entry, plus exceedsThreshold
POST /timer/start409 when one is already running
POST /timer/stop
GET /summaryToday's total, exceedsThreshold, serverTime
GET /stats?tz=…The unbilled total
GET /entries?from=…Today's rows
PATCH /entries/:idRename
GET /projects, GET /clientsThe picker and client colours
  • Never pre-check the running timer. Attempt the insert and translate the conflict — a pre-check is a race, the index is not. A 409 refreshes rather than reports: another device won and the invariant held, so showing what is running is more use than the error.
  • Tick locally, reconcile at 60s and on open, skew-corrected from serverTime. A Mac with a wrong clock would otherwise show a wrong elapsed time, which in this app is a wrong number on an invoice.
  • Today's total adds live seconds from the fetch, not from startedAt — the route already folded the running entry in, and adding it again counts it twice.
  • The task field follows the server only when unfocused, so it never overwrites itself mid-type.
  • Unbilled is never labelled "earned" or "revenue". It is work done and not yet invoiced — money the user might still never see. Show unbilled.total alone; the per-client breakdown is a web surface. When unratedCount > 0 the total is incomplete, and saying so beats a confidently wrong number.
  • The API models are hand-written and nothing type-checks them against packages/schema, so a renamed field fails at runtime in Swift and nowhere else.
Colours, type roles and the transport button come from packages/design-tokens and timer-bar.tsx. The strip is a mock — macOS spacing and the system font will differ.

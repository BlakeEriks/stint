The strip

The strip and the two time inputs are one value with two controls. A drag rewrites the fields on every pointer move; typing a time redraws the block.

  • It runs horizontally. The dialog is a column of rows, and at the calendar's 44px/hour a day is ~700px of dialog to adjust two fields. A vertical grid would also read against the left-to-right Start → End pair directly beneath it.
  • The block takes its client's color through useProjectColors(), so the same entry is the same color here and on the calendar. The accent in this dialog is Save.
  • The handles straddle the block's edges. At MIN_ENTRY_MINUTES the block is ~27px however tightly the window crops; two inset 10px handles would leave 7px of body, making the move gesture unreachable on exactly the entry most likely to be a mistake worth dragging.
  • Nothing commits on release. The strip writes the draft and Save writes the server, like every other field here. useEntryDrag PATCHes on pointer-up because the calendar has no Save to wait for; for the same reason this needs no drag threshold, the block not being the control that opens the editor.
  • The handles are not focusable. Start and End with step="900" are the keyboard path to the same two values, and arrow keys already step the quarter hour the drag snaps to.

Depth increases toward what is being read, and the ground is flat: the rail and dock are painted straight onto it, so the only edge in the frame belongs to the panel. brand.html carries the ramp.

The inset layer is a LIT top edge in dark and a SHADED one in light: a shadow needs headroom below the ground and dark has it, while light has headroom nowhere above bg-base, so the edge inverts.

  • Nothing inside the panel is a card. A region is marked by an inset rule and the space around it, so the whole column reads as one surface.
  • An inbox row keeps a small surface — it is there to be acted on, and an object you act on is an object.
  • The active rail item is a filled pill with a marker at its left edge. It marks which section you are in.
The content column

Page owns the measure, so no screen sets its own width.

PropertyValue
Measure48rem, or 72rem with wide
Top paddingSteps at lg — the nav's breakpoint, not its own
Horizontal paddingSteps at sm

The top padding follows the NAV because at lg the rail sits beside the content and the column opens against the top of the frame, wanting the full 40px. Below it the nav is a strip directly above, and the same 40px reads as a gap rather than margin.

  • A region's rule is inset — a mx-4 border-t div holding the same padding as the rows below it. A rule running edge to edge cuts the panel in two, which reads as two stacked surfaces.
  • The default Button is neutral; the accent is opt-in, because the running timer already holds it.
  • Buttons and nav carry icons, and an additive action carries a +. Icons are aria-hidden, so the accessible name stays the label alone. They never appear alone in nav — an icon is a fast second channel for a destination you already know and useless for one you do not.
The account menu

In the header: the signed-in email, and Sign out.

  • The email is the account. There is no name, avatar or organisation, so the one thing left to do with it is leave — Settings is a rail section and the theme is a field inside it.
  • Dark and light only. The palette is dark-first, so "System" would resolve to dark for everyone including a viewer whose OS is light — a control that appears to do something and does nothing. deriving-colour.md says what to change to follow the OS for real.
  • The theme carries no save indicator. It is a device preference in localStorage rather than a row on user_settings, so it applies on the click and there is no request to report.
  • Sign out is signOut() then router.replace('/signin') AND router.refresh(). The server components were rendered for a signed-in user, so without the refresh a Back navigation shows cached authenticated markup. Relatedly, request() sends any 401 to /signin — without it a signed-out page sat on "Loading…" forever, since React Query has retry: false.

The content column is replaced; the timer keeps counting

(app)/error.tsx is nested inside the group, so it replaces the content column and nothing else. That placement is the point: the timer is billable work in progress, and a full-page error screen that unmounts it is the app losing track of time it was trusted to keep. reset() re-renders the segment without a reload, so the local tick survives the recovery.

global-error.tsx is the last resort, for the root layout itself failing. It renders its own <html> and cannot use the design tokens — the stylesheet is imported by the layout that is not rendering — so its styles are inline token values. That is the one place in the app where a hardcoded hex is correct, and it is dark unconditionally since nothing is there to stamp [data-theme].

Both show error.digest when present. Next withholds a server error's message in production, so the digest is what ties the screen to the server log and makes a bug report actionable.

/throw is a development-only route that exists to test this, because nothing else in the app can be made to fail from the outside: a missing invoice renders "Not found.", a failed fetch renders its own message, a 401 redirects. notFound() makes it a 404 in production. e2e/error-boundary.spec.ts asserts the rail AND the stop button survive — moving the boundary to the root fails that test, which is the property jsdom cannot check.

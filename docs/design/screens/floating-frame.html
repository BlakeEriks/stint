The floating frame

The frame every screen renders inside: a continuous ground with one borderless panel floating on it. This is the agreed treatment in both themes, plus the decision table it settled on.

This is the visual reference the implementation answers to. Its numbers are the ones a build is measured against — pane widths, gaps, the grid’s columns and which regions pair in them. Read them out of here before changing the frame, and diff the built screen against them afterwards with getBoundingClientRect() rather than by eye: a 372px dock beside a 286px one, and a 20px gap where this has 8, both survived being looked at repeatedly.

The exploration that produced it — the rejected grounds, the hairline-border variants, the shadow studies — is not here. docs/design/principles.md holds what was decided against; a design doc carries the final form only.

The panel, in both themes

The pairing needs no new token: the ground is bg-base, already what the rail and dock are painted in, and the panel keeps bg-primary. The edge is a lit top inset and nothing else — no border, no lip beneath.

The treatment does not port. It inverts, and the reason is the same measurement that decided dark mode — where the headroom is.

ModeGroundLHeadroom toward the edge's direction
Darkbg-base0.1860.814 above — lit top edge
Lightbg-base0.9510.049 above — nothing to lighten toward

In light there is almost no room above bg-base, and the panel at bg-primary already spends 0.022 of the 0.049 available. A lit top edge there is invisible. But shadow — which had nowhere to go in dark — now has the entire range beneath it.

So the light panel is shaded from above rather than lit: a hairline of darkness along the top edge, and a real fall beneath. Same idea, same single inset layer, same "one object lit from above" — the light is simply coming from outside the screen instead of from the token ramp.

Two rules from the existing docs changed with it, and both are now recorded in the doc that owns them:

  • The four planes get new assignments. frame.html has header and timer bar on bg-recessed, rail and dock on bg-base, content on bg-primary, cards on bg-elevated. Here bg-recessed goes unused in the frame, and bg-elevated is no longer the content plane's card layer because there are no cards in it. The ladder is unchanged; what sits on each rung is not.
  • The active rail item stops being a tab. frame.html's reasoning — it lifts to the content plane and takes the card shadow, which is what makes the rail read as a tab strip into the column beside it — depends on a shared edge that no longer exists. It is a filled pill with a leading marker instead.

Scope: this is a frame change. Every screen renders inside it, so it belongs in frame.html rather than home.html, and the home card set is what motivated it rather than what contains it.

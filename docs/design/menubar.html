Stint in the menu bar

One design, three states. Built from the app's own tokens and components — same accent, same neutral ramp, same mono readout, same round transport button as the docked timer bar. Rendered at 320px, a real popover width.

This is the visual reference. The implementation spec is docs/design/menubar.md beside this file — sizes in points, token names, API calls, and the decisions that do not survive being drawn in HTML. Where the two disagree, the markdown wins.

  • The mark stays; its fill is the state. Mark.swift already draws the |S| — an S between two bounds, carrying what the letter cannot: a stint is work with a start and an end. A separate pip beside it was considered and dropped, because that puts two state indicators in a 100pt strip when the mark already tints.
  • Three fills, not two. Accent running, the bar's own foreground stopped, amber past the threshold. The amber case is the one likely missing today, and it matters most — it is how a runaway reaches someone whose panel is closed.
  • Stopped shows today's total, running shows elapsed. Both are worth a glance, and the fill says which you are reading.

Running · ~370px tall
  • Stop sits beside the readout, not top-right. The two things are one fact — this is running, and this stops it — so they belong on one line. Top-right puts a destructive-ish control in the corner where window chrome lives, and separates it from the thing it acts on.
  • Task and client hang under the readout, indented to the text rather than the dot, so the eye reads time → what → whose without crossing back.
  • Today and Unbilled are the two numbers you cannot compute in your head. Same pair the web app leads with.
  • The accent appears exactly twice: the pip and the readout. Same fact, shown twice — which the rule permits.

Stopped · ~340px tall
  • No 0:00:00 readout. The current design gives the biggest element on screen to a stopped clock. Nothing is accruing, so there is no number to show — the input takes that space, because starting is the only thing you came here to do.
  • The green is on the start button, alone. One accent object, and it is the primary action — exactly the rule the landing page follows on a screen with no timer.
  • Same stats, same entry list as the running state. The two states differ only in their top block, so the popover does not appear to restructure itself when you hit start.
  • Project picker inline beside the button saves a full row of height versus a full-width dropdown.

Runaway · entry list drops
  • This is the reason the menu bar app is worth building. Forgetting to stop at 5pm is the most common way a tracker produces a wrong invoice, and this is the only surface that catches it without you opening anything.
  • Amber, never green. The readout, the dot and the strip pip all move together, so the warning reaches you while the popover is closed.
  • Keep does not stop the timer. A long timer is often correct, and stopping it would be the app editing billable work.
  • The entry list drops in this state — when something needs deciding, the popover should not also be a dashboard.
Decisions still open
QuestionOptionsMy read
Strip: show the time at all? Mark + elapsed · mark only Show it — the whole point is a glance that costs no click. A mark-only mode is worth offering as a preference for people with crowded menu bars.
Stop button placement Beside the readout · top-right corner Beside — the timer and its stop are one fact. The corner is where window chrome lives, and it separates the control from the thing it acts on.
Entry list length 3 · 5 · scrollable 3, then "Open Stint" — a scrollable list inside a popover is fiddly, and the full day is one click away.
Can you rename a running entry here? Yes, inline · no, only in the app Yes — "what was I doing" gets answered late more often than on start, and a menu bar that can only stop is half a tool. Costs a pencil affordance on the task line.
Does Unbilled belong here? Yes · Today only Yes — it is the number no other tracker can show, and it is the difference between a timer widget and Stint in the menu bar.
Sign-out / account In the popover footer · only in the app Only in the app — the current design spends a footer row on an email address. You know who you are; put Open Stint and Quit there instead.
Global shortcut to start/stop Ship it · later Ship it — the fastest possible start is never opening the popover at all, and it is the one thing a menu bar app can do that the web app cannot.
Colours, type roles and the transport button come from packages/design-tokens and timer-bar.tsx. The strip is a mock — macOS spacing and the system font will differ.

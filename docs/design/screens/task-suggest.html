Typed “in” · matches ranked by recency, Ledger’s own first
  • A suggestion, never an autofill. The field keeps exactly what was typed; choosing a row is the only thing that writes it. A name that completed itself to the wrong client’s task is a wrong invoice line.
  • The match is highlighted, not the row. Weight marks the substring that matched; the accent is the running timer’s and does not appear here.
  • The project fills an empty field and never overwrites a chosen one. The label says which client this name was last used for — the disambiguator when the same name exists under two of them. Choosing the row sets the name always, and the project only when none is selected: a fill is a convenience, an overwrite would re-bill work to another client without the project control being touched.
  • The key to press is shown, not assumed. A keycap on the highlighted row says ↵ accepts it. It rides the highlight — appearing on arrow or hover, gone when nothing is selected — so it is only ever on screen while it is true. One hint: the arrows are found by pressing them and Escape is universal, but a list that fills a field on a key nobody guessed is a feature nobody finds.
  • Four rows, then stop. The list is a shortcut past typing, not a browsable history; a scrolling panel over the content column costs more attention than the keystrokes it saves.

Keyboard
KeyResult
↓ / ↑Moves the highlight, and with it the ↵ keycap. The arrow that points at the list enters it, landing on the row adjacent to the field — ↓ for a list below, ↑ for one above, as in the timer bar. The opposite arrow walks back and leaves, restoring what was typed.
Enter, a row highlightedFills the field with that name, and the project if none is chosen. Does not start the timer or save the entry.
Enter, nothing highlightedThe field’s own action — starts the timer, saves the entry.
EscapeCloses the list, keeps what was typed. A second Escape reaches the dialog.
TabCloses the list and moves on. Tab never chooses.

Nothing is highlighted when the list opens, so Enter means what it meant before the list existed — a timer started by typing and pressing Return never takes a name its typist did not finish.

What the rendering cannot show
  • Matching and ranking are the server’s. The endpoint returns names already ordered; the client filters the list it holds as characters arrive but never re-ranks. Two orderings of the same names is the bug where a row moves under the cursor.
  • The field owns its value; the list is told. TaskSuggest takes value and onChange and renders the caller’s own input, so the timer bar keeps its two-row phone layout and the dialog keeps Input. A component that owned the input would have to reproduce both.
  • The list is role="listbox" on a combobox field, with aria-activedescendant naming the highlighted row. The input keeps focus throughout, which is what makes typing and arrowing the same gesture.
  • Not a Radix popover. A popover moves focus to itself and traps it; every keystroke here belongs to the input. An absolutely positioned list under a relative wrapper is the whole mechanism.
  • The rename field has no list. Renaming a running timer is a correction to one entry, and a list of other names is an invitation to retarget billable work that is already counting.

One arrangement holds every state. Identity holds the left edge and the readout the right, so the clock lands in the same place whether a timer is running, idle or overdue — the number a glance goes to does not move as the name beside it changes length. The bar sits under the panel at the panel's width, which is what keeps the two ends reading as one object.

Running — one row; the pill is dropped, not wrapped

Running is one row because a running timer is being glanced at, not operated: the task name and the clock are what a glance is for, and the project is already fixed for the duration of the entry. Dropping the pill is what buys the row — wrapping it would spend a second line on the one thing that cannot change until the timer stops.

Idle takes two, because both its fields are inputs. The task field wants the width to be typed into and the picker has to stay reachable, so neither can be dropped the way the pill can.

What the rendering cannot show
  • The running task name is text, with an explicit rename button. As a live <input> a stray click renamed billable work, and the bar looked like a form waiting for input on every screen. The pencil is always rendered — hover does not exist on touch, and this is the one control with no other route.
  • The name shrinks but never grows. The clock is placed by margin-left:auto, so a greedy name would push the readout off its edge. Shrink-only keeps the right edge fixed and lets a long name truncate instead.
  • No project picker while running. Changing it mid-entry reassigns time already tracked against the old project, which is a billing edit wearing a dropdown. Stop the timer to move the work. The pill is the same shape either way; what changes is that running it is a span with no chevron, so the one thing a press would silently re-bill is the one thing that does not offer one.
  • The label is the project; the colour is the client. useProjectColors() resolves a project to its client's colour, so one line carries both facts and spends words on only the one that cannot be inferred. Two projects for the same client share a swatch, which is the grouping being shown rather than stated.
  • Round marks state, square marks work. Two small coloured marks sit on the same line, and shape tells them apart — the round one is the timer, the square is what is being billed. Colour cannot do it: both would be green often enough to confuse.
  • The first row is one grouped element, dissolving at sm with contents. Flex-wrap moves items before it shrinks them, so as loose siblings the pill took a line of its own instead of letting the name truncate beside it.
  • The runaway bar does not grow. Chrome must not reflow to report a problem. The choice — Keep · Adjust · Discard — lives in the inbox; screens/home.html specifies it.
  • useRunaway holds that state (lib/client/use-runaway.ts), because the row and the editor Adjust opens are in different components: the inbox is in the dock, the EntryDialog stays here. The stopped entry crosses between them through a small module-level store rather than a provider wrapping the whole app to carry one occasional value.

Entering seeds the draft from the server's name, so the draft and the mode are one piece of state that cannot disagree. focus() must precede select() — selecting does not focus, and without focus the field opens with no cursor and never fires the blur that commits.

Counting

useTimer counts locally from startedAt and reconciles with /summary every 60s and on focus. serverTime corrects a skewed device clock.

  • Before hydration it counts from the server's timestamp, not Date.now() — otherwise SSR and the client render different seconds and React reports a mismatch.
  • Today's total subtracts the running timer's elapsed-at-fetch before adding the live count, or the running time is counted twice.

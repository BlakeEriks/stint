  • Nothing inside the panel is a card. A region has no background, border, shadow or radius of its own; an inset rule is the only edge between two.
  • Each region owns its own autosave, so the indicator refers to the fields being looked at. One indicator for the page could only say that something saved.
  • A hint sits under the field it qualifies, and only where the field's own label cannot carry it.
Saving

Edits persist 700ms after typing stops. There is nothing to review before committing, so a button would only be a step between deciding and having it apply.

  • Idle is a dot, not a checkmark. A check that is always present says nothing and stops being read; this one appears only after a save the user caused, so it answers "did that land?" and nothing else.
  • Idle still occupies the space — the row would otherwise reflow the moment a save starts.
  • Pending is set on the EDIT, not on the request, so a field is never shown as saved while it holds unsent text. It stays pending through the debounce and the request both.
  • An edit during an in-flight request is queued, not raced. Without that a slow first response can land after a newer one and the server keeps the older value.
  • The error state is worded, not colored alone. "Not saved" is the one state a glyph cannot carry, because it is the one the user has to act on.

  • Appearance carries no save indicator. The theme is a device preference and applies on click, so there is no request to report — an indicator would imply it syncs.
Invoice numbering
  • The next number is server-owned and never goes back. Gapless numbering depends on allocate_invoice_number() holding the row lock, so the client strips this field from every patch it sends rather than trusting the form not to include it.
  • The payment notice is a standing line under the payment block. Details that never change are what make a change worth challenging, which is the whole anti-fraud argument for printing bank details identically every time.
Payment details
  • Resolution mirrors rates: the client's own profile, else the user's default. A dangling reference falls back rather than rendering nothing.
  • One default, enforced by a partial unique index, and the first profile created becomes it automatically. So "Make default" appears on every row except the one that already is.
  • A refused "Make default" names its row. One mutation serves every profile, and this is the setting that decides which account prints on an invoice — a failure that lands at the foot of the region could not say which one was refused.
  • Invoices freeze the rendered snapshot at generation, like rates. Editing a profile never alters an issued invoice.
  • No profiles is a stated outcome, not an empty list: "Invoices will render without a payment block."

Typed, after a failed request · the error sits above the button that failed
  • The first step is quiet; the second spells it out. The region's button is a ghost in text-danger; the red fill is spent on the dialog's confirm, which says "and data" because that is the consequence.
  • The dialog counts what goes. "All your data" is abstract; 37 invoices is the number that makes someone stop and download them.
  • Typing the email is the gate, not a checkbox. It cannot be clicked through by habit, and it names which account, for someone signed in to more than one.
  • It is all or nothing. One transaction removes every row the user owns and then the auth user, so a failure leaves the account whole and the error can say "nothing was removed".
  • Success signs out and lands on /signin with "Your account was deleted." There is no screen after it to return to.
  • No accent here. The dialog's one confirm is destructive, so green does not appear in it at all.

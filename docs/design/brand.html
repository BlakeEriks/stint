The mark, the type and the colour

Identity as it stands. Every value on this page is read from packages/design-tokens/tokens.json through screens/_mockup.css, so the mark you see here is the mark the products draw — this page cannot show a stale one.

Screen-level specs live in screens/. The menu bar app is menubar.html; the marketing page is landing.html.

The mark

The mark is |Stint| — the word between two bounds, set in one colour. The bounds carry what the letters cannot: a stint is work with a start and an end, which is also what a calendar block draws and what an invoice line is. The word sits inside them rather than beside them.

Construction

Every measurement is a multiple of the mark's own font size, so one definition serves every size it is set at. The values live under brand.mark in tokens.json and generate into CSS custom properties and Tokens.swift together — the web app and the macOS app read the same numbers.

PropertyTokenValueWhy
Bound width --mark-bound-width 0.09em Matches the stroke weight of the letterforms at semibold.
Bound height --mark-bound-height 1.05em Overshoots the cap height top and bottom. At 17px a bound cut to the cap height reads as a dot; the overshoot is what keeps it a bar at the smallest size the mark is set.
Gap --mark-bound-gap 0.18em Each side. Closer and the bound touches the S; wider and the three parts stop reading as one object.
Radius --mark-bound-radius 999px Fully rounded ends, so the bound is a drawn rule rather than a rectangle.
Type type-wordmark mono 600
0.12em		 IBM Plex Mono, semibold, 0.12em tracking. Mixed case — the S needs a cap to be taller than.

The bounds are drawn rules, not pipe characters. A | glyph carries its own side bearings and sits on the text baseline, so it renders shorter than the cap height and too far from the letters — the mark reads as "l Stint l".

The mark takes one colour

One value for the whole mark, bounds included. It inherits currentColor, so the bounds track whatever the word is set in and the mark works on a dark ground and a light one without a second definition.

  • text-strong is the default. The mark is a link to Home on every screen, so it is held to AA as body text — text-subtle measures 3.73:1 on the light header and clears only the large-text exemption.
  • text-muted where the mark recedes. The landing page's footer mark is set in it while the header's is not. The colour is passed in as a whole utility, not a shade parameter, so the bounds keep tracking it.
  • Never green. The accent means the running timer. A green mark would be a second meaning for it on a screen where the timer is already green.
  • Never a lifted S. The mark is one object and takes one value. Two greys a step apart read as a rendering fault rather than emphasis.
  • Never uppercase. STINT is four identical-height letterforms with no ascender to give the word a shape.
  • Never on the invoice PDF. An invoice is billed from the user's business, not from Stint. The PDF carries their name and their logo.
Typefaces

Two families, both IBM Plex. Mono is not decorative here — it carries every number the product is trusted with, and durations and amounts are always tabular so digits do not shift as they count.

Plex Mono over the usual candidates because its digits stay open and legible at 13px, which is the macOS menu bar size.

A component names a role

It never assembles one. Each role generates a real Tailwind @utility carrying family, size, weight, tracking, case and tabular-nums together, so half a role cannot be applied — and colour stays separate, because a role says how text is set, not what it means. Need something the scale lacks? Add a role, with a reason.

pnpm check:type runs in CI and rejects arbitrary sizes, arbitrary or preset tracking, bare font-mono/font-sans, Tailwind's own font scale, and any type-* that is not a real role — that last one matters because a typo'd role compiles to no CSS, no warning, exit 0. src/components/ui/** is exempt: vendored shadcn, policed by shadcn-detox.mjs instead.

Six roles step up at sm — hero, hero-strike, figure, timer, lede and display. Each is large enough that its desktop size would force a horizontal scroll on a narrow phone, and a component writing sm:text-3xl itself is the one-off the scale replaces — so the step belongs to the role.

  • Numbers are always a mono role. No exceptions.
  • Running text stays near 65 characters.
  • Task names truncate rather than wrap. An entry row is one line, which is what makes a dense list scannable.
  • type-nav is not type-label. Navigation is scanned and clicked constantly; a field label is read once while filling a form. Nav also takes less tracking — 0.16em at 13px sprawls. Inactive items use text-muted, not text-subtle, which is 3.14:1 on bg-base and fails AA.
  • type-section is not type-heading. A section heading sits above content already on the page; a card heading names a panel.
  • A card whose point is one figure demotes its own title to a quiet type-label above a type-figure the eye lands on. A card whose point is a list keeps its type-heading. Passing a value to Card selects the first mode.
The colours that mean something

The full palette, both ramps and the derivation is deriving-colour.md. These four are the ones that carry meaning, and confusing them is how the app starts lying.

accent-default #52FC43 · the running timer
success #2CCCEB · paid, saved, done
timer-warning runaway, overdue soon
danger something is wrong
  • Green marks the live, primary thing on a screen. Inside the app that is the running timer. The test: could a user say in one short phrase what green means on this screen, and would it be true of every green thing in view? If it takes two phrases, one of them loses the accent.
  • Green never means success. Success is cyan.
  • Never white text on the accent — 1.37:1. Use text-on-accent. CI guards this one.
  • Focus rings are neutral, never the accent. A focus ring is constant and involuntary; spending the accent there drowns the signal it exists for.

It is a test, not a quota — green may appear as often as that one idea genuinely occurs. The landing page sets three ticks and a CTA in it because all four are "what Stint does for you"; a green link beside a green timer fails, because that needs two phrases.

Success is not green

Green is a state channel: continuous, present tense, time is accruing right now. Success is an outcome channel: discrete, past tense, entry saved. Two different categories, so two different hues — and green never means "done" anywhere in this UI.

Info is deliberately the dullest of them. It is a passive colour, and low chroma keeps it from competing with the three that are not.

Four planes

Content floats; chrome recedes. Depth increases toward what is being read. Never invert it — a card darker than the surface under it reads as a hole.

bg-recessed header, timer bar
bg-base rail, dock
bg-primary content column
bg-elevated cards, + shadow-card

Depth comes from surface colour and shadow. Judge adjacent surfaces by OKLCH ΔL, never by WCAG contrast — WCAG is compressive near black and reports a near-invisible pair as 1.03:1 whether it is invisible or not. The four planes sit an even ΔL 0.035 apart.

The frame rises toward the card in both themes. The nearest plane is the lightest either way: a near-black card on a blacker frame, or a white card on a grey one. Light is not the mirror of dark — only the ink inverts, darkening to gain contrast where dark ink brightens.

Shadows are generated tokens, theme-aware. An alpha that reads as depth on a near-black ground looks like soot on a light one.

Client colours

Eight hues at fixed L 0.70 and C 0.11, varying only hue and excluding the accent zone 142±22°. Fixed lightness below the accent's 0.87 means a chip can never out-bright the running timer; chroma 0.11 against its 0.26 means it can never out-saturate it. Coherence is automatic because only one dimension varies.

  • Only clients have a colour. A project is a subdivision of a client already identified by it — the name answers which piece? and the colour answers whose work is this?, which is the question that recurs in a calendar, a heatmap and an invoice. useProjectColors() resolves project → client → colour.
  • Internal work gets no colour, rather than a shared grey that would read as a client of its own.
  • Charts use the two dedicated categoricals (#64A3E3 / #F6964E) on the blue/orange axis, the only axis dichromats retain. Minimum pairwise ΔE across the eight is 0.075 — fine for labelled chips, where text carries the identity, and not for a chart.
  • Only semantic tokens reach components. Primitives stay in the token package.

A week spent entirely on one client reads as a single colour. That is honest — it was a single client's week, and time of day plus the task label carry the rest.

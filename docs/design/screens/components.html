Composing a page

What to reach for before writing a div. Every screen in the app is these pieces in a different order, and the ones that drifted drifted because someone rebuilt a piece that already existed.

The skeleton

A screen is a Page holding a header and one kind of body. The frame around it — header, rail, dock, timer bar — is frame.html's, and a screen never draws any of it. 

// The whole shape of a list screen.
<Page>
  <header className="flex items-center justify-between gap-3 pb-4">
    <h1 className="type-title text-strong">Clients</h1>
    <Button asChild><Link href="/clients/new">…</Link></Button>
  </header>

  <nav aria-label="Filter">…</nav>   // if the list has views
  <ul>…</ul>
</Page>
  • Page owns the content column — width, gutters and the inset above the first card. No screen sets its own width, and none adds a top margin: the column already has one, and a second stacks.
  • wide is for a grid, not a preference. The calendar's seven days need the room; prose does not.
  • The page title is type-title, once. A card's own heading is type-heading.

Conventions that repeat
  • A list filter lives in the URL. FilterTabs draws the pills, marks the active one aria-current="page", and gives the default view no query at all. The view is then linkable and Back returns to it — /invoices and /clients both do this, and a component reading useSearchParams needs a Suspense boundary in its page.tsx or next build fails while next dev passes.
  • Every action carries a visible label. Two exceptions, both requiring aria-label: a destructive first step, and a dense repeating row where the label would not fit (the dock, a calendar cell). A glyph is always aria-hidden, so the accessible name stays the label.
  • An icon joins the label only for a verb the user scans for — the table below is the whole vocabulary. A label that names something unique to one screen takes no icon: "Mark sent", "Generate invoice", "Download PDF" are already the shortest thing they could be, and a glyph invented for them is one more shape to learn. Cancel takes none either; it undoes an intent rather than performing one.
  • The primary confirm action is variant="accent" — a form's submit, a dialog's Save. One per screen; everything else is neutral or ghost. A running timer in view is not a reason to demote it: the timer is green because it is live, the button because it is what finishes the screen, and a dialog over the timer bar is still allowed its Save.
  • A destructive action is quiet until it is the confirm. First step is a ghost trash icon in text-danger, pushed away from the confirm with mr-auto so a mis-slip cannot land on it; variant="destructive" is spent on the second step, which spells the consequence out in words.
  • A failure renders beside the thing that failed. One mutation serving many rows means a message at the foot of the card cannot say which row was refused.
  • An empty state says what to do, or what the consequence is — "Add one to set a rate and bill against it", not "No clients."
  • Archive, never delete, wherever invoices or entries reference the record.

The one exception to the accent row is the screen-level error boundary, which replaces the content column while the timer bar keeps running underneath: its "Try again" stays neutral so green still means the timer on the one screen where that reassurance matters most. error-boundary.test.tsx enforces it.

One icon, one meaning — the third column is the test. A Check that marks an invoice paid is reporting an outcome, not committing a form, so it takes the money glyph the inbox already uses. A creating form's submit is still Check: it commits, and Plus is what opened it.

Panel, Listing, Empty, FilterTabs, DetailPage

All of them live in page.tsx beside Page, because they are the column's furniture rather than any one screen's. 

// A list, and the three messages standing in for one.
<Panel>
  <Listing query={q} empty="Nothing yet. Add one to…">
    {(rows) => <ul>…</ul>}
  </Listing>
</Panel>

// A screen about ONE record says so when it is gone.
<Listing query={q} missing="That client no longer exists.">…</Listing>

// The filter above a list, in the URL rather than in state.
<FilterTabs base="/clients" active={status} tabs={[…]} />

// A group of panels, aligned whether or not each has a colour.
<Panel edge color={client?.color}>…</Panel>

// A detail screen.
<DetailPage back="/clients" label="Clients">…</DetailPage>
  • edge is opt-in, and a null colour still reserves the rail. Panels in a group must align whether or not each client has a colour — "No client" is a grouping rather than a record, so it gets the space and no colour. A standalone panel omits edge and has nothing to align with.
  • Listing renders loading, failure and empty, so no screen writes those branches. Before it, ten screens wrote two of the three and none wrote the third — a query that errored said "Loading…" for as long as the screen stayed open.
  • A failed load is neutral, never red. It is a condition rather than a rejected action, and the answer is to try again. Red stays on the danger channel.
  • panel wraps the MESSAGE alone, for a list whose rows are cards of their own — a panel around those would nest a card inside a card.
  • Empty takes tight for the in-page variant: today's entries sit under a heading that already has space above it, where a list filling its own panel does not.
  • back is where the record sits, not where you came from. The arrow promises "back" while the href means "up", so arriving from the home inbox and clicking it lands on a list you were never on. tasks.md carries the fix — and it is now one change rather than three, which is the argument for the component.
Adding a component
  • A component names a type role (type-amount), never assembles one (font-mono text-[15px]). check:type rejects the second in CI, and a typo'd role compiles to no CSS with exit 0 — which is why it is a check rather than a convention.
  • Colour comes from a semantic token. There is a utility for every legitimate colour and none for anything else.
  • Vendored shadcn goes through shadcn-detox.mjs, which rewrites its palette names to ours. Two of them mean the opposite of ours, and Tailwind drops an unknown utility silently.
  • Put it in components/ when a second screen needs it, not in anticipation of one. A local helper used once is not drift; the same helper in three files is.

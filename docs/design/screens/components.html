Composing a page

What to reach for before writing a div. Every screen in the app is these pieces in a different order, and the ones that drifted drifted because someone rebuilt a piece that already existed.

The skeleton

A screen is a Page holding a header and one kind of body. The frame around it — header, rail, dock, timer bar — is frame.html's, and a screen never draws any of it. 

// The whole shape of a list screen.
<Page>
  <header className="flex items-center justify-between gap-3 pb-4">
    <h1 className="type-title text-strong">Clients</h1>
    <Button asChild><Link href="/clients/new">…</Link></Button>
  </header>

  <nav aria-label="Filter">…</nav>   // if the list has views
  <ul>…</ul>
</Page>
  • Page owns the content column — width, gutters and the inset above the first card. No screen sets its own width, and none adds a top margin: the column already has one, and a second stacks.
  • wide is for a grid, not a preference. The calendar's seven days need the room; prose does not.
  • The page title is type-title, once. A card's own heading is type-heading.

Conventions that repeat
  • A list filter lives in the URL. nav aria-label="Filter" of Link pills above the list, aria-current="page" on the active one, and the default view has no query at all. The view is then linkable and Back returns to it — /invoices and /clients both do this, and a component reading useSearchParams needs a Suspense boundary in its page.tsx or next build fails while next dev passes.
  • Every action is icon plus label. Text, colour and glyph together beat any one channel. The glyph is aria-hidden, so the accessible name stays the label. Cancel is the exception: it undoes an intent rather than performing one.
  • Buttons are neutral unless the screen has one true primary action and no timer in view. The accent marks the running timer; variant="accent" is opt-in per screen.
  • A failure renders beside the thing that failed. One mutation serving many rows means a message at the foot of the card cannot say which row was refused.
  • An empty state says what to do, or what the consequence is — "Add one to set a rate and bill against it", not "No clients."
  • Archive, never delete, wherever invoices or entries reference the record.
Panel, Empty, DetailPage

All three live in page.tsx beside Page, because they are the column's furniture rather than any one screen's. 

// A list, and the message standing in for one.
<Panel>
  {isLoading ? <Empty>Loading…</Empty>
   : rows.length === 0 ? <Empty>Nothing yet. Add one to…</Empty>
   : <ul>…</ul>}
</Panel>

// A group of panels, aligned whether or not each has a colour.
<Panel edge color={client?.color}>…</Panel>

// A detail screen.
<DetailPage back="/clients" label="Clients">…</DetailPage>
  • edge is opt-in, and a null colour still reserves the rail. Panels in a group must align whether or not each client has a colour — "No client" is a grouping rather than a record, so it gets the space and no colour. A standalone panel omits edge and has nothing to align with.
  • Empty takes tight for the in-page variant: today's entries sit under a heading that already has space above it, where a list filling its own panel does not.
  • back is where the record sits, not where you came from. The arrow promises "back" while the href means "up", so arriving from the home inbox and clicking it lands on a list you were never on. tasks.md carries the fix — and it is now one change rather than three, which is the argument for the component.
Adding a component
  • A component names a type role (type-amount), never assembles one (font-mono text-[15px]). check:type rejects the second in CI, and a typo'd role compiles to no CSS with exit 0 — which is why it is a check rather than a convention.
  • Colour comes from a semantic token. There is a utility for every legitimate colour and none for anything else.
  • Vendored shadcn goes through shadcn-detox.mjs, which rewrites its palette names to ours. Two of them mean the opposite of ours, and Tailwind drops an unknown utility silently.
  • Put it in components/ when a second screen needs it, not in anticipation of one. A local helper used once is not drift; the same helper in three files is.
